# Security Policy

## Supported versions

Security fixes are made for the **latest release** of each integration. Please update before reporting; if the problem is already fixed in the latest release, updating is the fix.

## Reporting a vulnerability

Please **do not** open a public issue, discussion or pull request for a security problem.

Use GitHub's private vulnerability reporting in the affected repository: **Security → Advisories → Report a vulnerability**. Only the maintainers can see the report.

Please include:

- the affected repository and version
- steps to reproduce or a proof of concept
- the potential impact (for example: which data could be exposed)

Never include real credentials, device IDs or other personal data in a report; replace them with placeholders.

## What to expect

- We acknowledge your report within **7 days**.
- We keep you updated while we investigate and work on a fix.
- We publish a fixed release and a security advisory, and credit you in the advisory unless you prefer to stay anonymous.

These integrations are maintained in our spare time; complex issues can take longer to fix, but we will keep you informed.
